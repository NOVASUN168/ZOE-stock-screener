# ZOE 股票筛选器 · 前端响应式改造方案

> 目标：用同一套代码同时服务桌面端与移动端，后续功能修改只改一处即两端生效。
> 版本：V1.2.0（响应式改造完成）

---

## 1. 改造前现状

改造前的前端是**单文件内联结构**：

- `ui/index.html`：把 HTML 结构、内联 `<style>`（约 170 行）、内联 `<script>`（约 1000 行）全部写在一个文件里。
- 样式没有任何设计令牌，颜色、间距、字体散落在各处；暗色模式与涨跌配色靠硬编码类名实现。
- 没有响应式断点，移动端打开页面只能看到被压缩的桌面布局，表格完全不可读。
- 业务逻辑（筛选、预警、组合、复盘、方案、账户）与通用能力（弹窗、状态、API）全部混在一起，难以复用。

## 3. 响应式断点规则

| 断点 | 范围 | 布局策略 | 导航方式 |
|------|------|----------|----------|
| 手机 | < 640px | 单栏，所有列表卡片化，表单堆叠 | 底部主导航 + 抽屉全站菜单 |
| 平板 | 640px–1023px | 单/双栏混合，表格可横向滚动或卡片化 | 底部主导航 + 抽屉全站菜单 |
| 桌面 | 1024px–1279px | 顶栏 + 标签栏，工作台多列，方案三栏并排 | 顶部标签栏 |
| 大屏 | ≥1280px | 容器加宽，表单可双列 | 顶部标签栏 |

主切换点：**1024px**。≥1024px 显示桌面标签栏，隐藏底部导航与抽屉；<1024px 反之。

### 关键 CSS 变量

```css
--breakpoint-sm: 640px;
--breakpoint-md: 768px;
--breakpoint-lg: 1024px;
--breakpoint-xl: 1280px;
--breakpoint-2xl: 1440px;
```

### 显隐工具类

```html
<div class="only-desktop">桌面端才可见</div>
<div class="only-mobile">  移动端才可见</div>
```

实现上**只负责隐藏，不负责指定 display**：通过 `@media (max-width: 1023px) { .only-desktop { display: none !important; } }` 保证组件原生的 `block/flex/grid/table` 在可见断点不被破坏。

## 4. 组件拆分与复用策略

### 4.1 设计令牌（Design Tokens）

`tokens.css` 集中管理所有视觉常量：

- 颜色：品牌色、中性灰、语义色（成功/警告/错误/信息）、市场涨跌色（`--mkt-up` / `--mkt-down`）。
- A股红涨绿跌为默认，`[data-market-color="global"]` 时反转。
- 暗色主题通过 `[data-theme="dark"]` 仅覆盖表面、文本、描边等必要变量，不重新定义组件样式。

### 4.2 双端数据表格（datatable.js）

同一数据源渲染两套 UI，维护成本只增一处：

```js
renderDataTable(el, {
  columns: [...],
  rows: [...],
  renderCard: (r, idx) => '...',  // 可选：自定义卡片
  emptyText: '暂无符合条件的数据'
});
```

- **桌面**：`<div class="table-scroll only-desktop"><table class="table">`，容器自带横向滚动兜底。
- **移动端**：`<div class="dcard-list only-mobile">`，每张卡片自带操作按钮。

### 4.3 五维雪花图（snowflake.js）

```js
snowflakeSVG(stockRecord, size, showDimBars);
attachSnowZoom(svgElement);
```

- SVG 使用 `viewBox` + `width:100%`，任意容器都能自适应。
- 支持滚轮缩放、双击还原、移动端双指捏合。
- 详情弹窗中的雪花图配合 `.snow-figure` 容器实现居中、缩放、触控。

### 4.4 抽屉 + 底部导航（responsive.js）

- 移动端底部导航常驻 5 项：工作台、预警、组合、复盘、更多。
- 「更多」呼出左侧抽屉，抽屉内包含全部 8 个面板入口 + 主题切换 + 涨跌配色 + 账户区。
- 遮罩 `#scrim` 是 `.drawer` 的**兄弟节点**而非子节点，避免被抽屉的 `transform` 限制为仅覆盖抽屉宽度。

## 5. 共享状态与样式管理

### 5.1 状态管理

- `core/state.js` 暴露 `window.state` 单例，包含 `user/token/tier/catalog/schemes/...`。
- 所有状态变更函数通过 `localStorage` 持久化凭证，并在 `restoreSession()` 启动时恢复。
- 权限工具：`canEdit() / canAdmin() / canOwner()`，在业务组件中直接使用。

### 5.2 API 层

- `core/api.js` 统一封装 `api(method, path, body)`，自动注入 Bearer Token。
- 401 自动清空凭证并呼出登录框；403 给出 `premium_required` 提示。
- 所有业务视图只关心请求与渲染，不重复写 fetch。

### 5.3 主题与涨跌配色

- 主题：`data-theme="light|dark"`，持久化键 `zoe_theme`。
- 市场配色：`data-market-color="cn|global"`，持久化键 `zoe_market_color`。
- 首屏防闪烁：`<head>` 内联脚本在 HTML 解析前就读取 localStorage 设置属性。

### 5.4 样式加载顺序

```html
<link rel="stylesheet" href="assets/css/tokens.css">
<link rel="stylesheet" href="assets/css/base.css">
<link rel="stylesheet" href="assets/css/layout.css">
<link rel="stylesheet" href="assets/css/components.css">
<link rel="stylesheet" href="assets/css/components-extra.css">
<link rel="stylesheet" href="assets/css/charts.css">
```

`components-extra.css` 是**兼容层**：把旧内联样式中大量未迁移的类（`.risk-banner`、`.cat-item`、`.scheme-card`、`.pricing-grid`、`.userbox`、裸 `table/th/td` 等）用设计令牌重写一遍，避免改造后旧数据展示组件缺少样式。

## 6. 现有页面迁移步骤

本次改造已按以下顺序完成：

1. **备份原文件**：`ui/index.html` → `ui/index.legacy.html`。
2. **抽取 CSS**：
   - `tokens.css` 定义全部变量；
   - `base.css` 全局规则与显隐工具；
   - `layout.css` 响应式外壳；
   - `components.css` 原子组件；
   - `components-extra.css` 兼容旧类；
   - `charts.css` 雪花图与图表。
3. **抽取 JS**：
   - `core/`：主题、DOM、状态、API、响应式；
   - `components/`：弹窗、状态、数据表格、雪花图；
   - `views/`：8 个业务面板。
4. **重写外壳**：`index.html` 只保留响应式结构、全局导航、8 个 `.panel` 容器与脚本引用。
5. **增加服务端静态路由**：`server.py` 新增 `/assets/*` 路由，支持 MIME 映射、目录穿越防护、Content-Length。
6. **移动导航补全**：底部主导航 + 抽屉；遮罩提升为全局兄弟节点。
7. **响应式修复**：显隐工具改为单向 `!important`、移动端隐藏顶栏用户长胶囊、按钮触控区 ≥44px。
8. **三档视口验证**：桌面 1440 / 平板 768 / 手机 390 全部通过，零 JS 报错、零 4xx。

## 7. 后续维护约定

### 新增一个业务面板

1. 在 `ui/index.html` 中新增 `<section class="panel" id="panel-xxx">`。
2. 在顶栏 `.tabbar` 与底部导航 `.bottom-nav` / 抽屉 `.drawer-section` 中新增对应入口（标签文本一致）。
3. 新建 `ui/assets/js/views/xxx.js`，导出初始化函数并在 `app.js` 的 `switchTab()` 分支中调用。
4. 如需首屏加载，在 `app.js` 的 `init()` 中调用。

### 修改列表渲染

- 工作台、组合推荐、筛选方案结果均已使用 `renderDataTable()`，修改 `columns` / `renderCard` 即可同步影响桌面与移动端。

### 修改主题 / 颜色

- 只改 `tokens.css` 中的变量；不要在组件 CSS 里写死色值。
- 涨跌色相关必须使用 `--mkt-up` / `--mkt-down`，不要直接写红绿色。

### 新增 CSS 类

- 通用组件放 `components.css`。
- 与旧内联类重名或补充旧结构放 `components-extra.css`。
- 避免在组件样式中覆盖 `.only-mobile` / `.only-desktop` 的 display。

## 9. 可访问性要点

- 触控目标最小 44px（已校验通过）。
- 顶部包含 `skip-link` 跳到主内容。
- 弹窗与抽屉使用 `.is-open` 统一状态，关闭按钮有 `aria-label`。
- 尊重 `prefers-reduced-motion`：在 reduced motion 下关闭面板/抽屉过渡。
- 暗色主题下正文对比度满足 WCAG AA。

## 10. 已知可优化项

- 当前 JS 仍采用「全局函数 + script 顺序加载」模式，适合单页无构建环境。未来如需工程化，可平滑迁移到 ES Modules / Vite，设计令牌与组件结构保持不变。
- 图表缩放目前基于 SVG viewBox 与 transform；未来可引入轻量 D3/Charts 库替代手写多边形。
